# カテゴリ（`categories`）

ユーザーが作成する学習カテゴリ。

## カラム

| カラム名 | 型 | NULL | 既定値 | 説明 |
|---|---|---|---|---|
| `id` | number (auto-increment) | NO | 自動 | 主キー |
| `name` | string | NO | — | カテゴリ名（ユニーク） |
| `color` | string (hex) | YES | null | 表示色（円グラフ等で使用、例：`#FF6B6B`） |
| `sort_order` | number | NO | 0 | 表示順 |
| `deleted_at` | number (epoch ms) | YES | null | 論理削除時刻。null なら有効 |
| `created_at` | number (epoch ms) | NO | 自動 | レコード作成時刻 |
| `updated_at` | number (epoch ms) | NO | 自動 | レコード最終更新時刻 |

## インデックス

| 名称 | カラム | 用途 |
|---|---|---|
| `idx_name` | `name` (unique) | カテゴリ名の重複防止 |
| `idx_deleted_at` | `deleted_at` | 有効カテゴリのみの取得 |
| `idx_sort_order` | `sort_order` | 表示順での取得 |

## Dexie スキーマ例

```ts
db.version(1).stores({
  categories: '++id, &name, deleted_at, sort_order',
});
```

> `&name` は unique インデックス。ただし論理削除済みも対象になるため、削除時に `name` を `__deleted_<id>__name` のようにリネームするか、ユニーク制約を外してアプリ層で重複チェックする運用を検討（設計フェーズで確定）。

## TypeScript 型定義

```ts
export interface Category {
  id?: number;
  name: string;
  color?: string | null;
  sort_order: number;
  deleted_at?: number | null;
  created_at: number;
  updated_at: number;
}
```
