# 勉強記録アプリ - 要件定義書

## 1. プロジェクト概要

**アプリ名：** 勉強記録アプリ

**目的：** Web上で学習活動を記録・管理し、進捗状況を可視化する**個人用**アプリ。暫定的に自分専用のローカルツールとして利用する。

**プラットフォーム：** Web版（HTML/CSS/JavaScript）

**利用形態：**
- **シングルユーザー（自分専用）** — 認証・マルチユーザー対応は行わない
- **ローカル完結** — データは利用ブラウザ内（IndexedDB）に保存し、サーバには送信しない
- **配信：** GitHub Pages（HTTPS）で公開し、PC・スマホのブラウザから利用
- **開発環境：** Docker コンテナ上で開発・ビルドを行う（ホストマシンへの直接インストール不要）

---

## 2. 記録対象項目

ユーザーが記録できる情報：

- **勉強時間** - いつ、何分間勉強したかを記録（必須）
- **カテゴリ** - 勉強の科目を分類するためのカテゴリ（オプション、**1記録に複数付与可**）
- **教材名** - 使用した教材・参考書・コンテンツ名（オプション）
- **達成度** - その学習回での達成度合い（オプション、表現方法は設計フェーズで詳細化）
- **目標時間** - ユーザーが任意に設定する目標時間（**分単位**で入力。オプション）

---

## 3. 想定される利用シーン

複数の利用目的に対応：

- 学生の学校勉強（テスト対策・宿題）
- 資格試験対策（TOEIC、基本情報技術者試験など）
- スキル学習（プログラミング、言語習得など）
- その他カスタム用途

---

## 4. 主要機能

### 4.1 タイマー・計測機能
- **スタート画面** - 「勉強をスタート」ボタン
- **計測画面** - ストップウォッチ表示、シンプルなUI
  - 「休憩ボタン」：時間計測を一時停止（**休憩時間は学習時間に含めない**）
  - 「計測終了ボタン」：時間計測を終了し、学習時間を記録
  - カテゴリ選択（オプション、複数選択可）
- **離脱警告** - 計測中にアプリを閉じようとすると警告メッセージ表示
- **異常終了時の挙動** - 計測中にブラウザ／タブを閉じた場合、計測中のデータは**破棄**する（自動復元はしない）
- **バックグラウンド動作** - ブラウザのバックグラウンドタブでも計測時間が正確であること（`setInterval` のドリフト対策として、開始時刻との差分から経過時間を算出する方式を想定）
- **マルチデバイス** - 複数デバイスで同時に計測した場合、それぞれ独立した記録として保存される（デバイス間の同期・統合は行わない）

### 4.2 カテゴリ管理
- 複数のカテゴリを作成・編集・削除
- カテゴリを選択した状態で学習時間を記録

### 4.3 ダッシュボード（統計表示）
- **総勉強時間表示** - 合計学習時間（日単位・週単位・月単位）
- **カテゴリ別表示** - 総勉強時間とカテゴリ別に切り替え表示
- **グラフ・チャート表示**
  - 円グラフ（カテゴリ別の勉強時間割合）
  - 棒グラフ（日単位・週単位・月単位の勉強時間）
  - 折れ線グラフ（勉強時間の推移）

#### 集計ルール
- **タイムゾーン：** Asia/Tokyo（JST）固定
- **日単位：** 午前 0:00 〜 翌 0:00（JST）で区切る
- **週単位：** 週の起点は **月曜日**（月曜 0:00 〜 翌週月曜 0:00）
- **月単位：** 暦月ではなく **直近 30 日間** をロールウィンドウで集計
- **複数カテゴリの集計：** 1記録に複数カテゴリが付与されている場合の按分ルールは設計フェーズで詳細化

### 4.4 データ管理
- **保存先：** ブラウザの **IndexedDB**
- **サーバ送信なし：** バックエンド・クラウド同期は行わない
- 学習記録の一覧表示・編集・削除
- データモデル（学習記録・カテゴリのスキーマ、削除方式 等）は **DB 設計フェーズで別途詳細化**

#### データ保持に関する注意
- ローカル保存のため、**ブラウザのキャッシュクリア・別ブラウザ／別デバイスからの利用ではデータを参照できない**
- エクスポート／インポート機能は現時点では対象外（必要になったら検討）。そのため、ストレージ削除時のバックアップ手段は提供しない

---

## 5. 非機能要件

### 5.1 パフォーマンス
- ページロード時間：2秒以内
- ダッシュボードの集計表示：200ms以内（数年分の記録を想定）

### 5.2 ユーザビリティ
- レスポンシブデザイン（モバイル・タブレット対応）
- 直感的なUI/UX設計

### 5.2.1 対応ブラウザ
- Google Chrome（最新安定版）
- Microsoft Edge（最新安定版）
- 上記以外のブラウザ（Safari, Firefox 等）は動作保証外

### 5.3 可用性
- GitHub Pages の稼働状況に依存（実用上は常時利用可能）
- データはブラウザのローカル領域にあるため、ホスティング先のダウン時もデータ自体は失われない

### 5.4 セキュリティ
- 個人利用のため、認証は不要
- サーバ送信を行わないため、通信経路上のデータ漏洩リスクは対象外
- 配信は GitHub Pages の HTTPS で行う

## 6. 技術スタック（推奨）

### フロントエンド
- **フレームワーク：** React / Vue.js / Svelte（または Vanilla JS）から設計フェーズで選定
- **スタイリング：** Tailwind CSS / CSS Modules
- **グラフ表示：** Chart.js / Recharts
- **データ保存：** IndexedDB（ラッパーライブラリとして Dexie.js 等の利用を検討）

### バックエンド
- **採用しない**（ローカル完結のため）

### 配信
- **GitHub Pages** — ビルド成果物を配信。GitHub Actions で自動デプロイ

### 開発環境
- **Docker** — 開発サーバ・ビルドをコンテナ内で完結させる
  - `docker compose up` で開発サーバ起動
  - ホストマシンへの Node.js 等の直接インストール不要

### 開発ツール
- **ビルドツール：** Vite / Webpack
- **CI/CD：** GitHub Actions（main ブランチへの push をトリガーにビルド → GitHub Pages デプロイ）
- **テスティング：** Jest / Vitest
- **バージョン管理：** Git

---

## 7. 開発フェーズ

### Phase 1：MVP（最小機能構成）
- タイマー機能（スタート・休憩・終了）
- カテゴリ管理（作成・編集・削除）
- 基本的なダッシュボード（総勉強時間表示）
- IndexedDB へのデータ保存
- GitHub Pages へのデプロイ（GitHub Actions による自動化）

**推定期間：** 2-3週間

### Phase 2：拡張機能
- ダッシュボードのグラフ表示（円グラフ・棒グラフ・折れ線グラフ）
- カテゴリ別表示の切り替え

**推定期間：** 2-3週間

---

## 8. 成功基準

- ✅ 学習時間を素早く記録できる（記録開始まで 2 タップ以内）
- ✅ 統計情報をひと目で確認できる
- ✅ PC・モバイルブラウザの両方で快適に利用できる
- ✅ 自分が継続的に使い続けられる

---

## 9. 制約事項

- **シングルユーザー（自分専用）**。マルチユーザー・認証は対応しない
- **データはブラウザローカルに保存**。別デバイス／別ブラウザとの同期はしない
- ブラウザのストレージ削除でデータが消失する（バックアップ手段は現時点で未提供）
- iOS ネイティブアプリ化、PWA 化は本要件のスコープ外（必要になったら別途検討）
